# claude — Claude Code config + shared agent commands

Manages Claude Code's user-level config and the slash-command library that is
**shared with the Oh My Pi (`omp`) harness**.

## What this package manages

| Path                                                                    | Form                          | Why                                                                                                       |
| ----------------------------------------------------------------------- | ----------------------------- | --------------------------------------------------------------------------------------------------------- |
| `~/.claude/commands/*.md`                                               | per-file symlinks             | Claude Code user commands. Per-file so unmanaged local commands can live alongside them                   |
| `~/.omp/agent/commands`                                                 | directory symlink             | Same files, exposed to `omp`'s **native** command provider. Nothing else writes here                      |
| `~/.local/bin/claude-turn-*`                                            | symlinks                      | Stop / UserPromptSubmit hook scripts referenced from `settings.json`                                      |
| `~/.omp/agent/agents/*.md`                                              | per-file symlinks             | Helpers that are omp agents (`## Helpers`), plans' and Bruce's. Per-file: `omp agents unpack` writes here |
| `~/.local/bin/rename-census`                                            | symlink                       | Helper that is a command (`## Helpers`)                                                                   |
| `~/.claude/skills/<logos skill>`                                        | symlinks (via `configure.sh`) | Every `<logos>/skills/<name>` fleet does not keep logos-only; no copy, no drift possible                  |
| `~/.claude/{CLAUDE.md,SHARED.md,COMMUNICATION.md,DOTFILES.md,TESTS.md}` | per-file symlinks             | Machine-wide instructions. `SHARED.md` is the part both harnesses read                                    |
| `~/.omp/agent/AGENTS.md`                                                | per-file symlink              | omp's user context file: one line, `@~/.claude/SHARED.md`                                                 |
| `~/.omp/agent/skills`                                                   | symlink (via `configure.sh`)  | Points at `~/.claude/skills`, so omp offers the same skills as Claude Code                                |

## Skills payload

Every skill's source lives in the repo it describes, and `~/.claude/skills` holds only links
to it — never a folder of its own:

- this package's own skills (`home/.claude/skills/`) and agent-web's are linked by dot;
- logos' skills are source code in logos, one folder each under `<logos>/skills/`.
  `configure.sh` links every one of them, except a skill logos links from its own committed
  `.claude/skills/` — that one is logos-only (`kit`, `ui`, `effect`) and loads only inside
  logos. There is no list here: adding a skill, or making one logos-only, is a logos commit,
  and the next `dot pkg claude configure` links it or removes the link. The checkout path is
  the per-host record `packages/dot/bootstrap.sh` writes;
- `playwright-cli` is generated by the CLI into a cache and linked by agent-web's
  `configure.sh`;
- `~/.claude/skills/synced` is Claude Code's own download of claude.ai skills — the one folder
  here nothing in dot writes.

## Helpers

A helper is recurring fetch work given a name, a fixed procedure and a fixed answer shape, so
every session that calls it fetches the same way. A helper reads and returns; only the calling
session writes. This section is the one place that says where helpers live and how one is added.

- **An omp agent**, `home/.omp/agent/agents/<name>.md`, when the job needs judgement: which
  source settles a question, which practice is current. Its answer shape is the `output` schema in
  its frontmatter (JSON Type Definition, as omp's bundled `scout` uses), and `structured: true`
  makes omp check every answer against it. After three failed attempts omp accepts the answer
  anyway with a `SYSTEM WARNING: Subagent exhausted schema-retry budget` line: that warning in a
  helper's result means its definition needs fixing. Its model is a role alias (`@task`), so model
  IDs stay in `~/.omp/agent/config.yml`. omp only: Claude Code reads `~/.claude/agents` in another
  format (other tool names, no answer schema), and omp never reads that directory.
- **A command**, `home/.local/bin/<name>`, when the job is deterministic. Its answer shape is its
  header comment. Both harnesses can run it.

| Helper           | Kind    | Called from                                             | Answers with                                                                                               |
| ---------------- | ------- | ------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `fact-check`     | agent   | `plans` skill, `design.md` step 3                       | per question: answer, sourced or unverified, sources with quotes                                           |
| `field-survey`   | agent   | `plans` skill, `design.md` step 3                       | options: how, who, available at the versions in use, sources                                               |
| `bruce-scout`    | agent   | `bruce-plan`: `phase.md`, `start.md`, `returns.md`      | per question: answer, found or not, path:line refs with quotes                                             |
| `bruce-catch-up` | agent   | `bruce-plan`: `catch-up.md`, `start.md`                 | proposals (add/replace/drop, file, current, new, source with quote)                                        |
| `bruce-review`   | agent   | `bruce-plan`: `ship.md`                                 | verdict, gates, findings (consequence, who, why, where, fix)                                               |
| `bruce-rereview` | agent   | `bruce-plan`: `ship.md`                                 | per finding: consequence and fix, each with a quote; per question: answered, premise-false or beyond-reach |
| `bruce-verify`   | agent   | `bruce-plan`: `phase.md`                                | per gate and criterion: verdict, screenshot; records created, left                                         |
| `rename-census`  | command | `plans` skill, `design.md` step 4 and the rename lesson | one line per hit, tracked or untracked, path hits, counts per repo                                         |

The Bruce helpers are called from a session whose working directory is `/data/code/work/bruce`:
a subagent gets its caller's rules, and the Bruce rule packs (`rule://…`) resolve only there.

`rename-census` limits: `-i` covers letter case only (`fooBar` and `foo_bar` are separate runs), a
tracked file deleted in the working tree still shows as a path hit, and submodules are not
searched.

### Adding or changing a helper

1. Write the file.
   - An agent lists only read tools in `tools` (`read, grep, glob, find, web_search`), unless its
     job cannot be done without running commands. Then it lists `bash`, and its allowlist goes
     into the helper guard (`packages/omp/hooks/pre/helper-guard.ts`, the omp package README)
     before the agent file is linked: omp has no per-agent command rule, and with a bare `bash` a
     helper can write, as one did (a research subagent appended to logos' `.gitignore`,
     workflow 04).
   - Never give an agent a bundled agent's name (`scout`, `reviewer`, `security-reviewer`,
     `task`, `sonic`): a user agent replaces the bundled one silently.
   - dot's linker skips a file named `README.md`, `configure.sh`, `CHEATSHEET.md`, `setup.sh` or
     `meta.json`, or starting with `enable` or `disable` (`SKIP_NAMES` in logos'
     `apps/dot/src/lib/pkg.ts`).
   - A command is POSIX `sh`, and `shellcheck -s sh` and `shfmt -d -i 2 -ci` print nothing on it:
     `just check` covers only `*.sh`.
2. `dot pkg claude link`, then `dot pkg claude status`.
3. Run its smoke call below from a fresh shell and read the answer. A new helper adds its own
   smoke call here, with a known answer where one exists.

### Smoke calls

`omp -p` prints the calling model's reply, which paraphrases the helper's answer, and a long
answer reaches it only as a preview. `--mode json` prints every event instead; the `wait` or
`task` result carries the helper's own schema-checked answer as `structured` (`status` `valid`,
and `data` holding the answer). Each agent smoke saves the events, then shows that and counts
schema warnings.

```sh
omp -p --mode json --model @smol "Use the task tool with agent fact-check. Questions: 1. Does omp load task-agent definitions from ~/.claude/agents/? Versions in use: omp $(omp --version | cut -d/ -f2). Then reply DONE." > /tmp/smoke-fact-check.jsonl
jq -s '[.[] | .. | .structured? | select(type=="object")][0] | {status, data}' /tmp/smoke-fact-check.jsonl
grep -c 'SYSTEM WARNING' /tmp/smoke-fact-check.jsonl || true
```

Expect, in about a minute: `status` `valid`, one answer, its `status` `sourced`, the answer "no",
a source with a quote (omp's own docs or its `src/task/discovery.ts`); the warning count `0`. A
`jq` that prints `null` means no helper answer was found: read the `.jsonl`.

```sh
omp -p --mode json --model @smol "Use the task tool with agent field-survey. Problem: before renaming a word or moving a file in a git repository, a person needs every place the old name appears, in file contents and file paths, split into committed and not-yet-committed files, one line per hit. Versions in use: git $(git --version | cut -d' ' -f3), ripgrep $(rg --version | head -1 | cut -d' ' -f2). Then reply DONE." > /tmp/smoke-field-survey.jsonl
jq -s '[.[] | .. | .structured? | select(type=="object")][0] | {status, data}' /tmp/smoke-field-survey.jsonl
grep -c 'SYSTEM WARNING' /tmp/smoke-field-survey.jsonl || true
```

Expect, in about five minutes: `status` `valid`, two to eight options, one of them `git grep` with
`git ls-files`, each with `available` and dated sources; the warning count `0`. There is no known
answer: read it.

```sh

git -C /data/config/dot grep -I -c -F 'fact check' | awk -F: '{s+=$NF} END {print s}'
```

Expect: the tracked count on the first line equals the number on the second.

## One set of instructions for both harnesses

omp does not read `~/.claude` at all by default: its `enabledProviders` setting starts
empty, and foreign user-level sources (Claude, Codex, Cursor…) load only when listed. So
`CLAUDE.md` and `~/.claude/skills` never reached omp, and each rule had to be bridged by
hand. `COMMUNICATION.md` never got a bridge and went unread by omp for a month.

Listing `claude` in `enabledProviders` would fix that, but it also pulls in Claude's hooks,
plugins, MCP servers and settings, and `config.yml` is not in this repo. Instead:

```
CLAUDE.md  = @~/.claude/WEB-VERIFY.md + @~/.claude/SHARED.md (+ Claude-only lines)
SHARED.md  = @~/.claude/DOTFILES.md + @~/.claude/COMMUNICATION.md + @~/.claude/TESTS.md
~/.omp/agent/AGENTS.md = @~/.claude/SHARED.md
```

- **A new machine-wide rule goes into `SHARED.md`**, not `CLAUDE.md`, so both harnesses read
  it. `CLAUDE.md` holds only what Claude Code alone should see.
- **`WEB-VERIFY.md` stays out of `SHARED.md` on purpose.** omp already reads it as a sticky
  rule (`~/.omp/agent/RULES.md`, from the agent-web package), which is resent with every
  request and reaches subagents. Importing it again would load it twice.
- **Every Claude profile reads the same file.** `configure.sh` links
  `~/.claude-work/CLAUDE.md` and `~/.claude-personal/CLAUDE.md` to `~/.claude/CLAUDE.md`;
  before that, the personal profile held a one-line real file and got only web-verify.
  Imports are absolute (`@~/.claude/…`) so they resolve the same way through those links.
- **omp subagents do not get `SHARED.md`**: omp strips files named `AGENTS.md` when it spawns
  one. Subagents do not talk to the user; the sticky web-verify rule still reaches them.

Verify both:

```sh
omp -p --model @smol "No tools. Does your system prompt contain 'The reader's attention is the scarce resource'? YES/NO"
CLAUDE_CONFIG_DIR=~/.claude-work claude -p --model haiku "No tools. Do your instructions contain 'The reader's attention is the scarce resource'? YES/NO"
```

## Sharing one command library across both harnesses

Canonical source: `home/.claude/commands/*.md`. One copy, two consumers.

```mermaid
graph LR
  A["packages/claude/home/.claude/commands/*.md<br/>(canonical, in git)"]
  A -->|per-file symlink| B["~/.claude/commands/*.md"]
  A -->|dir symlink via home/.omp/agent/commands| C["~/.omp/agent/commands"]
  B --> D["Claude Code"]
  C --> E["omp — native provider (priority 100)"]
  B -.->|"also readable, shadowed"| E
```

`home/.omp/agent/commands` is a **relative symlink inside the repo**
(`../../.claude/commands`). dot's linker walks `home/` with `readdir` +
`Dirent.isDirectory()`, so a symlinked directory is emitted as a _single_ link
entry rather than being traversed — `~/.omp/agent/commands` becomes one symlink
that chains through the repo to the real command directory.

### Why the two sides use different link granularity

- **`~/.claude/commands` is per-file.** Claude Code itself writes into this
  directory, and non-dot local commands should be able to sit next to the
  managed ones. Cost: adding a new command file needs `dot pkg claude link`
  before Claude Code sees it — the normal dot workflow for every package.
- **`~/.omp/agent/commands` is the whole directory.** No `omp` feature writes
  user commands there (`omp agents unpack` targets `~/.omp/agent/agents`), so
  owning the whole path is safe and means new commands appear in `omp`
  immediately, with no re-link.

### Duplicate discovery in omp is expected and harmless

`omp` finds each command twice: once via the `native` provider
(`~/.omp/agent/commands`, priority 100) and once via the `claude` compat
provider (`~/.claude/commands`, priority 80). Capability dedup is first-wins by
name, so `native` always wins; the loser is kept only in the shadowed list shown
by the Extensions dashboard.

To silence the shadow entries entirely, set in `~/.omp/agent/config.yml`:

```yaml
commands:
  enableClaudeUser: false
```

Left at the default (`true`) on purpose — it keeps any _unmanaged_ command
dropped into `~/.claude/commands` visible to `omp` too.

### Profile caveat

The native symlink covers the **default** `omp` profile only. Named profiles
read `~/.omp/profiles/<name>/agent/commands`. Add one symlink per profile under
`home/.omp/profiles/<name>/agent/commands` if you start using them.

## Adding a command

```sh
$EDITOR /data/config/dot/packages/claude/home/.claude/commands/my-command.md
dot pkg claude link   # links the new file into ~/.claude/commands
```

`omp` picks it up with no re-link. Verify both harnesses:

```sh
omp   -p '/my-command'
claude -p '/my-command'
```
