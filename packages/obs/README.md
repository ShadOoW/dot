# obs

macOS-only (`meta.os = ["macos"]`). OBS Studio on the MacBook records each meeting: the
screen, the microphone and Chrome's audio, into an MKV in `~/Movies/meetings`, both audio
tracks lossless (FLAC, 48 kHz). At the same time it streams a lighter copy to snake over the
tailnet (SRT to `snake.tail.shadhq.com:8793/udp`: H.264 at 1500 kbps and the two voices as
separate Opus tracks), reconnecting by itself. The stream can fail without touching the file.

This package holds the `meetings` profile and scene collection, and `configure.sh`, which
copies them into OBS's settings. It does not start or stop anything: egghead's `bin/obs`
(`start`, `stop`, `status`, run on the desk) drives OBS over obs-websocket, and OBS's own
Start Recording and Start Streaming buttons reach the same outputs. Nothing here deletes a
recording. The design is egghead's `.plans/study-21j-recorder.md`.

| File                                                      | Role                                                                  |
| --------------------------------------------------------- | --------------------------------------------------------------------- |
| `obs-studio/basic/profiles/meetings/basic.ini`            | outputs: recording (MKV, FLAC tracks 1+2) and stream (SRT, Opus 1+2)  |
| `obs-studio/basic/profiles/meetings/*Encoder.json`        | H.264 on the hardware encoder: 6000 kbps recorded, 1500 kbps streamed |
| `obs-studio/basic/profiles/meetings/service.json`         | the stream's destination: SRT caller to snake, 8793/udp               |
| `obs-studio/basic/scenes/meetings.json`                   | sources `Screen`, `Mic/Aux` on track 1, `CallAudio` on track 2        |
| `obs-studio/user.ini.seed`                                | seeded once: open on `meetings`, skip the setup wizard                |
| `obs-studio/plugin_config/obs-websocket/config.json.seed` | seeded once: websocket server on 4455, password generated by OBS      |
| `configure.sh`                                            | copies the five files above, seeds the two seeds                      |

## Applying it

Quit OBS first; `configure.sh` refuses while OBS runs, because OBS rewrites its settings
when it quits, over anything copied now.

```sh
osascript -e 'tell application "OBS" to quit'
bash ~/code/dot/packages/obs/configure.sh
open -a OBS
```

`dot pkg obs configure` runs the same script but asks for sudo first; the script needs
none.

## Copied, never linked — and what that costs

Unlike `packages/hammerspoon`, nothing here is a symlink, and the files sit in
`obs-studio/`, outside `home/`, so dot's linker cannot reach them:

- **OBS replaces its own settings files when it saves.** It writes a temporary file and
  renames it over the old one (`config_save_safe`, `os_safe_replace` in libobs). A link
  would silently become a real file at the first save.
- **obs-websocket writes its file in place, through any link, with its password in it.**
  Linked, the password would land in this repository.

So `dot doctor` cannot see drift here. A change made in OBS's settings window to the
`meetings` profile or collection lasts only until the next `configure.sh`. To keep one,
copy the changed file from `~/Library/Application Support/obs-studio/` back into
`obs-studio/` and commit it.

## The seeds

`user.ini` and `plugin_config/obs-websocket/config.json` are OBS's to write: they hold the
window layout, the last profile used and the websocket password. `configure.sh` installs
them only when absent (`seeded`), and otherwise leaves them alone (`kept`).

- The `user.ini` seed names the `meetings` profile and collection, with `FirstRun=true`,
  which skips OBS's setup wizard.
- The websocket seed enables the server on 4455 with no password. On its first load
  obs-websocket generates one and saves it; `bin/obs` reads it from that file over
  `ssh mac` at each call. It has one home, this Mac, and is never in git. A lost file is
  seeded again and OBS makes a new password; nothing else changes.

## Values true of this Mac only

- `display_uuid` of the `Screen` source, in `meetings.json`. On another Mac it resolves to
  the wrong display or none, with no error: `bin/obs start` refuses a blank screen.
- Chrome's bundle id (`com.google.Chrome`) on the `CallAudio` source. While Chrome is not
  running that track records silence.
- The recording path `/Users/youneselalami/Movies/meetings` in `basic.ini`.

## macOS permissions

OBS needs **Screen Recording** and **Microphone** in System Settings → Privacy & Security.
An OBS update can drop them (it did with OBS 32.1); the screen then records black, which
is what `bin/obs start`'s blank-screen refusal catches. When `global.ini` is gone, OBS
shows its permissions dialog once at launch: one click, kept on purpose, because it is the
only place that says a permission is missing.

## Never turn on `RecordWhenStreaming`

With it, OBS starts the recording only once the stream has connected, and stops it when
the stream stops: snake being down at the start would mean no local file. The recording
and the stream are separate outputs here; `bin/obs start` starts the recording first, then
the stream, and the recording never stops with the stream.
