# oh-my-openagent — Ultimate edition

Wraps the `oh-my-openagent` OpenCode plugin so its config is reproducible across
machines via this dot repo. Installs the Claude-primary + Gemini-fallback agent
mapping that `bunx oh-my-openagent install --no-tui --claude=yes --gemini=yes ...`
generates, plus the `opencode-antigravity-auth` companion plugin for Gemini OAuth.

## What this package manages

| Path                                            | Form    | Why                                                               |
| ----------------------------------------------- | ------- | ----------------------------------------------------------------- |
| `~/.omo/omo.jsonc`                              | symlink | User-owned config; OpenCode reads it but does not atomic-rewrite  |
| `~/.config/opencode/opencode.json` plugin array | merge   | App-owned; OMO installer + Antigravity plugin entries, idempotent |
| `~/.config/opencode/tui.json` plugin array      | merge   | Same as above for the TUI-specific config                         |
| `~/.local/bin/ast-grep`                         | symlink | Surface the headroom-ai bundled binary on PATH so the skill works |

`~/.omo/omo.jsonc` was a real file generated by the installer. **If you ever see
`dot doctor` flag it as drifted (real file where a symlink should be)**, switch
this package to a `seed/` + `configure.sh` install-once pattern, modelled on
`packages/claude/`. Until then, symlink is fine — same reasoning: OpenCode reads
this file at startup but does not atomic-rename it the way Claude Code does to
`~/.claude/settings.json`.

## Re-install from scratch

```sh
# 1. Install the plugin (registers itself in opencode.json + writes ~/.omo/omo.jsonc)
bunx oh-my-openagent install --no-tui \
  --platform=opencode \
  --claude=yes --gemini=yes \
  --copilot=no --openai=no \
  --opencode-zen=no --zai-coding-plan=no --opencode-go=no \
  --kimi-for-coding=no --vercel-ai-gateway=no \
  --skip-auth

# 2. Adopt the generated config into this repo
mv ~/.omo/omo.jsonc /data/config/dot/packages/oh-my-openagent/home/.omo/omo.jsonc

# 3. Re-link + configure
cd /data/config/dot
bun dot.ts link oh-my-openagent
bun dot.ts configure oh-my-openagent   # idempotent plugin-array merge

# 4. Verify
bunx oh-my-openagent doctor
```

## Per-machine overrides

The OMO config precedence (per the install guide) is:

```
walked:  <pwd up to $HOME>/.opencode/oh-my-openagent.json[c]
        ↓ merged on top of
user:    ~/.config/opencode/oh-my-openagent.json[c]
        ↓ falls back to
defaults from ~/.omo/omo.jsonc
```

For per-machine tweaks (different `disabled_agents`, custom agent model
overrides, etc.), put them in `~/.config/opencode/oh-my-openagent.jsonc` — it is
**not** managed by this package and survives `dot link` because it is a separate
file OMO will pick up alongside the symlinked one.

## Telemetry

Telemetry is disabled via env vars in `packages/zsh/home/.zshenv`:

```sh
export OMO_DISABLE_POSTHOG=1
export OMO_SEND_ANONYMOUS_TELEMETRY=0
```

A config-file opt-out would be cleaner, but `~/.omo/omo.jsonc` is validated by
`OmoConfigSchema` (`.strict()`), which rejects unknown top-level keys. Adding
`telemetry: false` at the root produces `bunx oh-my-openagent doctor` failure
(`Invalid omo config at ...: `). The env-var path is the only one the runtime
actually checks (`shouldDisableTelemetry` in `telemetry-core/src/env.ts`).

## Verified OAuth flows

After `dot configure oh-my-openagent`, run `opencode auth login` and complete:

- **Anthropic → Claude Pro/Max** (browser OAuth)
- **Google → OAuth with Google (Antigravity)** (browser OAuth; required for the
  `google/antigravity-*` model variants the plugin installs)
